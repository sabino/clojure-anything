# clojure-anything

[Leia o guia em português](docs/pt-BR.md)

Turn data, source code, or a description of a program into Clojure (`.clj`) or ClojureScript (`.cljs`). The tool itself is written in Clojure and runs on Babashka.

| What you have | What you get |
| --- | --- |
| JSON, EDN, or plain text | A namespace with a `data` var, generated locally |
| A source file, project directory, or written specification | A project generated by Codex or an agent you supply |
| Commands that exercise a program | A recording you can replay against the port to check its behavior |

Choose `clj` for the JVM or for code you plan to run with Babashka. Choose `cljs` for JavaScript runtimes such as Node.js or a browser.

## Install

The converter requires Babashka 1.13.229 or newer. The examples below use a POSIX shell. [Babashka installation guide](https://github.com/babashka/babashka#installation).

```sh
git clone --depth 1 https://github.com/sabino/clojure-anything.git
cd clojure-anything
bb --version
bb clojure-anything --help
```

`bb --version` should print `babashka v…`. If another executable is using that name, use the full path to Babashka in the commands below.

## Convert data and load it

Run these commands from the `clojure-anything` checkout. The remaining examples reuse the temporary directory created here.

```sh
tool_dir=$PWD
work_dir=$(mktemp -d)
printf '%s\n' '{"greeting":"Olá","ready":true}' > "$work_dir/settings.json"

bb clojure-anything convert --namespace demo.settings --out "$work_dir/data" \
  "$work_dir/settings.json"

bb -cp "$work_dir/data/src" \
  -e "(require 'demo.settings) (println (get demo.settings/data \"greeting\"))"
```

The last command prints `Olá`. The converter created `data/src/demo/settings.clj` and `data/deps.edn` in your temporary directory. Use `--to cljs` to generate `settings.cljs` for a ClojureScript project.

Omit `--out` to print the generated source. When reading data from stdin (`-`), put options before `-` and select the format with `--from`.

```sh
printf '%s\n' '{:items ["maçã" "pera"]}' \
  | bb clojure-anything convert --from edn --to cljs -
```

The converter recognizes `.json`, `.edn`, and `.txt` by extension. Override that choice with `--from json`, `--from edn`, or `--from text`. JSON object keys remain strings and `null` becomes `nil`. Clojure preserves exact JSON decimals. ClojureScript uses JavaScript numbers and rejects EDN ratios, exact decimals, non-finite numbers, and integers outside the safe range.

## Record and replay a complete example

With Python 3 and Babashka, you can record the included Python CLI and replay its five cases against the Clojure port. [Original CLI](examples/textkit/original.py) · [Case file](examples/textkit/cases.edn) · [Clojure port](examples/textkit/ports/src/textkit/core.clj) · [ClojureScript port](examples/textkit/ports/src/textkit/core.cljs).

```sh
bb clojure-anything record examples/textkit/cases.edn "$work_dir/recording.edn" \
  -- python3 examples/textkit/original.py

bb clojure-anything check "$work_dir/recording.edn" \
  -- bb -cp examples/textkit/ports/src -m textkit.core
```

`record` writes a new EDN file. `check` should print `5/5 cases matched.` The cases cover a Unicode argument, environment variables, stdin, empty input, and an invalid command.

To check the ClojureScript port as well, install Java 21, the Clojure CLI, and Node.js. The compile step runs once and `check` then runs the built program for each case. [Clojure CLI installation](https://clojure.org/guides/install_clojure) · [ClojureScript quick start](https://clojurescript.org/guides/quick-start).

```sh
(
  cd examples/textkit/ports || exit
  clojure -M:cljs -t node -O none -o out/textkit.js -c textkit.core && \
    bb -cp "$tool_dir/src" -m clojure-anything.main check "$work_dir/recording.edn" \
    -- node out/textkit.js
)
```

### Write cases for your program

Each case has a unique `:name`. `:args` is a vector of strings appended to the command after `--`. `:stdin` is a string and defaults to empty input. `:env` adds or replaces variables for that case.

```clojure
[{:name "Unicode input" :args ["lines"] :stdin "Olá\n世界"}
 {:name "Prefix" :args ["echo" "hello"] :env {"TEXTKIT_PREFIX" "> "}}
 {:name "Invalid command" :args ["unknown"]}]
```

Each case runs in the current directory. The recording holds the cases, exit statuses, and exact stdout and stderr. Output that cannot be decoded as UTF-8 is stored as Base64. `check` prints the expected and actual values for fields that differ. It exits `0` when every case matches, `1` on a mismatch, and `2` on an input or execution error. The default timeout is 15 seconds per case, adjustable with `--timeout SEC` before the case or recording path.

For a library or HTTP API, give `record` and `check` commands that exercise the same interface and print the results you want to compare. Add representative and edge cases to cover the behavior you rely on.

## Generate a port with an agent

`--codex` uses the signed-in Codex CLI on your `PATH` and sends it the selected input and any supplied recording. `codex login status` shows whether the CLI is signed in. [Codex CLI](https://github.com/openai/codex).

Generate a Clojure port of the example using the recording you just made.

```sh
bb clojure-anything convert --codex --to clj --namespace textkit.generated \
  --cases "$work_dir/recording.edn" --out "$work_dir/generated" \
  --brief 'Use core Clojure and expose -main at textkit.generated.' \
  examples/textkit/original.py
```

Open the generated README for the build and run commands. Review the code, then pass its run command after `--` to `check`. The example below uses the Clojure CLI and prepares dependencies before replay so their download messages stay out of the comparison.

```sh
(
  cd "$work_dir/generated" || exit
  clojure -P && bb -cp "$tool_dir/src" -m clojure-anything.main \
    check "$work_dir/recording.edn" -- clojure -M -m textkit.generated
)
```

For a ClojureScript port, use `--to cljs` and a different `--out` directory. The agent defaults to Node.js for ClojureScript CLIs. Set the platform or dependencies explicitly with `--brief`. You can also write a specification directly on stdin.

```sh
printf '%s\n' 'Build a Node.js CLI that reads stdin and prints the longest line.' \
  | bb clojure-anything convert --codex --to cljs --out "$work_dir/longest-line" -
```

A source input can be a UTF-8 file, a directory, or stdin. For big repositories, give it one module at a time. Directory input is limited to 128 files and 512 KiB of text and skips hidden paths, symlinks, common build and dependency directories, and common binary assets and key files. To port from a Git repository, clone it and pass the source directory. Each source conversion requires a new output directory. The default agent timeout is 600 seconds.

### Use your own agent

To select an external agent, append `-- AGENT ARG ...` to `convert`. The command receives a UTF-8 prompt on stdin. The last line is a JSON object with `target`, `namespace`, `files`, and the optional `brief` and `recording`. The agent exits `0` and writes one JSON object to stdout, using relative paths and complete file contents.

```json
{"files":[{"path":"src/converted/core.clj","content":"(ns converted.core)\n(defn square [n] (* n n))\n"}]}
```

Include a `.clj` or `.cljs` file for the chosen target, or a portable `.cljc` file. Write agent diagnostics to stderr.

## Run from another directory

Use `bb -cp /path/to/clojure-anything/src -m clojure-anything.main` in place of `bb clojure-anything`. Relative input paths and commands resolve from the directory you run it in. Choose a fresh output path for a new conversion or recording.
